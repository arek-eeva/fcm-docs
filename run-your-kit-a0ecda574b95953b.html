01Set up Git

The one that catches people.

10 minutes if it's already there, up to an hour if it isn't

What it is. Git is a small background tool that keeps track of changes to files. You'll never open it or look at it. Claude needs it to work on files on your own computer, and your Chief of Staff uses it to keep a private history of your system, which is what lets any file be put back the way it was last Tuesday.

Most Macs already have it, which is why nobody thinks about it until they hit a machine that doesn't. If yours is one of those, Claude stops and says it can't proceed. That isn't you doing something wrong, it's a missing part.

Worth knowing up front

This is the single most common place people get stuck, and it happens to people who are perfectly comfortable with computers. It's also the one step nobody can do for you remotely, because on a Mac it ends in a system dialog that has to be clicked at your own keyboard. Read the whole of this section before you click anything.

On a Mac

Check whether you already have it

Open the Terminal app: press Command and Space, type "Terminal", press Enter. Then type this and press Enter:

git --version

A version number such as git version 2.50.1 means you're set. Skip to the Python check at the end of this step.

Anything else, including a window popping up offering to install "command line developer tools", means it isn't there yet.

If it's missing

Type this in Terminal and press Enter:

xcode-select --install

Click Install when the window appears, and let it finish. Then run git --version again and you should get a version number.

Two things about that install, because they're what make people think it's broken when it isn't:

  • It's big and slow. Roughly 2GB, and depending on your connection anywhere from a few minutes to the better part of an hour, with no useful progress detail while it runs.
  • The window can hide behind everything else. It's an ordinary Mac system dialog, so it can open behind your browser and sit there waiting for a click you never gave it. If nothing seems to be happening, check behind your other windows before assuming it failed.

If it goes wrong

  • "Can't be installed at this time", or it stops partway. Almost always Apple's servers being busy rather than anything at your end. Wait an hour and run xcode-select --install again.
  • It says the tools are already installed but git --version still fails. Run sudo xcode-select --reset, enter your Mac password when asked (the typing stays invisible, that's normal), then check again.
  • Not sure whether it worked? Run git --version. A version number means yes, anything else means no. That's the whole test.
On Windows

Install Git for Windows

Same requirement, easier install, no system dialog to hunt for.

  1. Go to git-scm.com/downloads/win and download the 64-bit installer.
  2. Run it and accept every default. There are a lot of screens and none of them need changing.
  3. Open the Start menu, type "PowerShell", press Enter, then type git --version and press Enter.

A version number means you're done.

Install Python too

Your kit uses Python for a handful of small jobs: giving each task a unique number, taking the snapshots that let a file be restored, and recording the licence against your business name. On a Mac it arrives with the Git install above. On Windows it's a separate two-minute job.

  1. Go to python.org/downloads and download the current version for Windows.
  2. Run the installer. Tick "Add python.exe to PATH" on the first screen before you click Install. This is the one box that matters, and it's easy to miss.
  3. Check it in PowerShell: python --version.
Your final check, either machine

Both of these should give you a version number. Mac: git --version and python3 --version. Windows: git --version and python --version. If they do, the hard part of setup is behind you.

On Windows, if your assistant ever hands you a command starting with python3 and Windows says it doesn't recognise it, type python instead. Tell your assistant you're on Windows and it will stop doing that.

03Unpack your kit

Get the folder into the right place, once.

5 minutes

Your kit arrives by email as a single compressed file, stamped with your business name and a purchase reference. Download it, then:

Unzip it

  • Mac: double-click the file. It expands into a folder next to itself.
  • Windows: right-click the file, choose Extract All, then Extract.

Choose where it lives

Move the unzipped folder somewhere that gets backed up. Documents is the right answer for most people, particularly if it syncs to iCloud Drive or OneDrive. The Desktop is the wrong answer: it's where things get dragged around and lost.

This is your business's operating system. Treat the folder the way you'd treat your accounts.

Pull the working folder out

Open the kit folder. Inside you'll find the written material you're reading now, and a folder called Starter-OS. Those are two different things:

  • The kit folder is the manual. Reference material you dip into, listed in step 13.
  • Starter-OS is the actual assistant. It's what you'll open every day.

Drag Starter-OS out so it sits beside the kit folder rather than inside it. Keeping them nested works, but it means your daily folder is buried one level down inside a folder you rarely open, and that's the sort of small friction that quietly costs you.

Name it

Rename the Starter-OS folder to your assistant's name. Give it one. People who name theirs talk to it more naturally, brief it better and get more out of it, and that isn't sentimentality, it's that you stop composing prompts and start talking to a colleague.

If you call yours Dotty, the folder becomes Dotty-OS. Tell your assistant its name in the first session and it'll use it from then on.

Two things not to do

Don't move the folder again once you've settled it, at least not without telling your assistant. It knows where it lives, and moving it is the sort of thing that produces a confusing morning.

Don't delete or edit the licence stamp. There's a small file at the folder root recording which business this copy is licensed to. Nothing reports anywhere and nobody can see inside your system. It stays.

While you're here

Most files in the kit end in .md, which is plain text with light formatting. On a Mac they open as raw symbols unless you install the small reader that ships with the kit. Your assistant does it for you: once you're up and running in step 4, say "install the Markdown Viewer from the kit folder for me". Full note in Install the Reader. Mac only.

04Open the folder and wake it up

The moment it becomes yours.

5 minutes, then it does the talking

  1. Open the Claude app and switch to the Code tab.
  2. Just above the message box at the bottom, there's a folder control. Click it and choose to open a folder.
  3. Point it at your renamed Starter-OS folder. Open it.
  4. When it asks whether you trust this workspace, say yes. It's your own folder.
  5. In the message box, type Hello and press Enter.

From now on the app opens straight into that folder. If you ever want to talk to your Chief of Staff, that's where it lives.

What happens next

Your assistant reads its operating brief before it answers anything, sees that the brief is still a blank template, and takes that as its cue. It greets you, tells you in a sentence what you're about to do together, and offers to set itself up.

Say yes, and it writes a visible plan into the folder called Setup-Plan.md so you can watch it tick items off:

  • Point it to your stuff. Your context folder, however messy.
  • Your website. It reads it for your brand, your tone and what you actually do, so you repeat less of it.
  • The drill. It interviews you about your business, your voice, your pricing and what matters right now, one question at a time.
  • It tidies up. Your dumped-in files get sorted and renamed into something sensible.
  • Your brief, and a first real win. It fills in the operating brief in your words, then does one real task with you end to end.
  • Licence it to your business. One command recording which business this copy belongs to. Seconds.

It pauses between items so you can stop whenever you like. When everything's ticked, it deletes the plan file and just gets on with being your Chief of Staff.

Before you go far

Set the permission mode to Auto now, so it isn't asking your approval for every small thing. It still asks before anything reaches outside your system. That control, and the rest of them, are in step 6.

05Bring your context

The difference between a clever chat and a Chief of Staff.

30 to 60 minutes of gathering, and it's the highest-value hour you'll spend

An assistant that knows nothing about you writes generic work. Everything useful it will ever do comes from what it knows about your business, and the fastest way to give it that is to hand over what you've already got.

What's worth gathering

  • Old AI conversations. If you've been using ChatGPT, Claude or anything else, export them. This is the single richest source, because it's months of you explaining your business in your own words.
  • Writing that sounds like you. Emails you were happy with, a proposal that won, a post that landed, a page off your site.
  • Your price list. Whatever form it's in. A scribble is fine.
  • The documents you reach for repeatedly. Your standard quote, your terms, your onboarding email, your checklist.
  • Your website address. It'll read the site itself.
  • Anything half-finished you've been meaning to sort out. Genuinely. The mess is informative.

The fuller list, with the reasoning behind each one, is in Your Homework in your kit folder.

Don't tidy it

Don't sort it, don't rename anything, don't make it presentable. Sorting it is one of the first things your assistant does, and seeing it in its natural state tells it more about how you work than a tidied version would. Tidying first is wasted effort that also destroys information.

The prompts, in the order you'll use them

Copy these, change the details to yours, and say them out loud rather than typing if you can. None of the wording is magic, and getting it slightly wrong costs you nothing. They're here so you're not staring at an empty box wondering how to start.

1. Hand over the folder

Drag the folder into the message box first, then send this with it.

This is everything I could find from the last couple of
years. It's a mess and I haven't tidied it, which I gather
is the point. Read through it before you ask me anything
you could work out from a file, then tell me three things
you now know about my business and two things you're still
guessing at.
2. Your website

Faster than describing your own business, and it catches the words you actually use.

My site is [yoursite.com]. Read it properly, then give me
your read of what I do, who I do it for and how I sound,
as a guess I can correct rather than a summary. Where the
site is out of date or says something I'd no longer claim,
say so, because I'd rather fix that than have you learn it.
3. Your voice

Point it at the writing samples specifically. This is what stops the drafts sounding like everyone else's.

The writing samples in that folder are mine and they're the
ones I was happy with. Work out how I actually sound:
sentence length, how formal I am, the words I reach for,
the ones I'd never use, how I open and close an email.
Write that up as my voice profile and keep it where you can
reach it, then draft me one short reply in it so I can tell
you what you got wrong.
4. Your prices

Get this in once, properly, and every quote afterwards comes out right.

Here's my pricing. Put it in my brief as the single place
prices live, so nothing quotes off a stale copy. Where a
figure is missing, out of date, or I've clearly been making
it up per job, ask me rather than guessing. Also tell me
which of my prices you'd expect a client to push back on,
and why.
5. The contradictions instruction

The one to give on day one. Old material always disagrees with itself.

You'll find contradictions in what I've given you: prices
that changed, things I renamed, two versions of the same
document. Don't pick a winner yourself. Spot them, mark
them, and bring them to me as decisions, one at a time,
with a recommendation and what it depends on. When I make
a call, apply it everywhere it reaches, not just where we
were looking.
6. Your week

This is what turns it from a writer into an operator. The answers become your first skills.

Ask me about my week: what I do on repeat, what always
slips, what I dread, and the one job I'd hand over
tomorrow if I could. One question at a time and dig into
the answers rather than moving on. At the end, tell me
which two of those you could take off me this month, and
what you'd need from me to do it.
7. What don't you know

Run this once setup is done, and again in a fortnight. It finds the gaps you'd never think to fill.

Based on everything you've read so far, what are the ten
things you still don't know about my business that would
most change the quality of your work? Rank them by what it
would cost you not to know, and ask me the top three now.
8. Lock in how it talks to you

Say this the first time a reply is longer than you wanted. The last two words are the important ones.

Answer first, keep it short, and skip the working unless I
ask for it. When you're not sure what I want, ask me one
question rather than writing three versions. Save that.

"Save that" is the phrase worth remembering. It's what turns a correction in this conversation into a rule that holds in every conversation afterwards.

Decision made is decision implemented

When you settle one of those contradictions, your assistant doesn't just record your answer. It goes back and applies it everywhere the contradiction reached. That's one of the things that makes this feel different from a chat window, and it's worth testing early so you trust it.

The one boundary

Keep this line

Your Chief of Staff handles the business layer: marketing, admin, scheduling, templates, content, pricing and general correspondence.

Client-identifying and sensitive personal information stays out of it. Health records, government identifiers, anything held under a professional duty of confidence. This protects you, your clients and your good name, and it's much easier to hold the line from day one than to clean up later.

Where your material actually goes

Said plainly, because you should know rather than assume. Your files stay in your folder on your computer. They aren't uploaded anywhere or stored by us, and we can't see inside your system. When your assistant needs to read something to answer you, the content of that file goes to Anthropic to be processed, in the same way anything you type into the app does. That's the boundary. It's why the rule above exists in the form it does.

06The interface, part by part

Five controls do ninety per cent of the work.

15 minutes, and worth reading properly once

Down the left: your sessions

Every conversation is a session, listed down the left the way chats are. Above them is a calendar that fills in as you use it, so you can see your own rhythm at a glance.

  • Rename them. You'll have several open at once before long, and "handover documents" beats a wall of identical entries.
  • Group them. Right-click to make groups and drag sessions in and out. Most people end up with a group per part of their business: client work, marketing, admin, the personal one.
  • One session, one subject. When a conversation has wandered a long way from where it started, start a fresh one. Nothing is lost by doing that, because your assistant's real memory lives in your files rather than in the conversation.

The permission button

Below the message box. It's the control that decides how often you're asked before anything happens, and it matters more than it looks.

SettingWhat it does
DefaultAsks before changing a file or running anything. Reading and looking around is free. Fine while you're finding your feet, tiring after a day.
AutoThe one to use. Approves the ordinary mechanical things without stopping, and still asks you for anything that matters. This is the setting that lets it get on with a long job.
PlanIt explores and writes out a full plan, and changes nothing until you approve. Reach for this on anything big or unfamiliar.
BypassApproves everything, including things you'd want to see. It exists, and it isn't recommended. Leave it alone.

Click the button to change it, or press Shift + Tab to cycle. Rule of thumb: plan for anything new or risky, auto the rest of the time.

What Auto never approves

Auto is about mechanical work inside your own folder. It doesn't loosen the gates. Sending an email, publishing anything, spending money and deleting things all still need your explicit yes, every time, in every session. That's built into your assistant's brief rather than into the button, so it holds regardless of which mode you're in.

Working with a plan

In plan mode, your assistant thinks it through and then opens the finished plan in its own panel, the whole approach laid out before anything happens. This is the cheapest moment to change direction, so read it.

Four choices sit at the bottom:

  • Reject. Wrong track. It starts over.
  • Revise. Tell it what to change and it re-plans, keeping what worked.
  • Accept. Good to go, checking in as it works.
  • Accept and auto. Go, and run the whole thing through without stopping.

The trick worth knowing: select any line in the plan to leave a comment right there. "Do this differently." "Drop this step." Far more precise than describing it from the top, and it's how you shape a big build into exactly what you wanted.

The model picker

Bottom right, showing the name of whatever model you're currently on. Click it to change. Full detail in step 7.

The usage ring

The small ring with a diamond in it. It's a set of dials showing what you've used against your plan's limits, and how full the current conversation is.

That second one is the one to watch. Every session has a working memory, and a long one fills it up. When it does, your assistant summarises the conversation so far and carries on, which is called compacting. Nothing important is lost when that happens, because your real memory lives in your files. You can ask for it yourself by typing /compact, or type /context to see what's taking up the room.

Slash commands worth knowing

CommandWhat it does
/modelSwitch model without reaching for the picker.
/effortSet how hard it thinks. See step 7.
/contextShow what's filling up this session.
/compactSummarise and carry on, freeing up room.
/undoRewind the last change. Pressing Esc twice does the same.
/feedbackReport a problem with the app itself to the people who make it.

You don't have to memorise these, and you don't have to use them at all. Your kit's skills have slash commands too, but plain English reaches them just as well: "interview me for setup" finds the same thing as typing the command, because your assistant knows what it has.

Stopping and steering

  • Stop it. Press Esc at any time. It halts and waits for you. Do this the moment you see it heading the wrong way rather than letting it finish out of politeness.
  • Correct it. Say what's off, plainly. "Too formal, warmer please." It takes the note and carries on.
  • Make it stick. For something it should never do again, tell it to remember: "Never use that phrase. Save that." From then on it holds across every future session, not just this one.
  • Undo it. Changed your mind after the fact? /undo, or Esc twice. Every edit can be rewound.

There's a longer version of this section in your kit: Driving Claude Code, one of the five reference cards.

07The model, and how hard it thinks

Two settings, and one of them is quietly costing people their results.

5 minutes

The models

They're named after literary forms, and the names tell you something. Haiku is the short one. Click the model name at the bottom right to switch.

ModelUse it for
HaikuThe sprinter. Renaming and sorting files, quick look-ups, bulk mechanical work. Still capable, but don't hand it your thinking.
SonnetThe daily driver. Quick and genuinely capable, and the sensible default for most jobs.
OpusThe deep thinker. Hard judgement, careful writing, anything where getting it right matters. Slower, and it uses your plan's allowance faster.

What I actually run: Opus, for nearly everything. The extra time it takes is repaid several times over in not having to fix the answer. Start on Sonnet if you'd rather feel your way in, and move up the moment you're doing something that matters.

How hard it thinks

Beside the model name is the effort setting, a slider running from low up through medium, high and higher still. Type /effort to reach it directly.

Effort is how much thinking it does before it answers. Higher means slower, better, and more of your allowance. High is a good home setting. Push it up for anything that deserves real thought: a proposal, a pricing decision, a piece of writing that's going to be read closely, a plan for something big. Drop it to low for grinding through a hundred files.

The trap

Whatever you picked last tends to carry into your next session, so it sticks quietly. If answers start feeling oddly literal, forgetful, or it keeps losing track of what you told it, check the picker before you conclude anything about the system. You're most likely on Haiku, or on low effort, from some bulk job three days ago. A surprising amount of "why is it being dense today" is this one setting.

You can also just ask. "Use Opus for this one" and "think harder about this" both work, mid-conversation, without touching a control.

08Attaching files

Three ways, all of them quick.

3 minutes

  • Drag and drop. Pull a file, or a whole folder, straight into the message box. This is the fastest way and it's what you'll use most.
  • The plus button. Beside the message box, if you'd rather browse to it.
  • Paste a screenshot. Take one and paste it straight in with Command + V (or Ctrl + V on Windows). Perfect for an error message or something you're looking at and can't describe.

Whatever you attach appears above the message box before you send, with a small x to remove it if you grabbed the wrong thing. Attach several at once if you need to.

For anything large or permanent, put the file into your folder and tell your assistant where it is, rather than attaching it every time. Attaching hands it over for that message. Filing it makes it part of your system.

Never attach or paste these

Passwords, API keys and access tokens don't go into the chat, ever. The conversation is saved, synced and sometimes screenshotted, so a key dropped there is exposed for good.

When you need to give your assistant a key, ask it to set that up properly: "I need to give you my [X] key safely. Make me a secrets file that stays out of backups, and tell me where to paste it." It creates the file, keeps it out of anything that gets published or backed up, and reads the key from there without ever printing it.

If one does slip out, treat it as burned. Go to the service, cancel the old key and generate a new one. It takes a minute.

09Dictating

Talk to it. Don't type at it.

5 minutes to set up, and it changes how you work

This is the habit that separates people who get a lot out of this from people who get a little, and it has nothing to do with typing speed.

When you type, you edit as you go. You compress, you leave out the background, you get to the point and stop. That's good writing and it's terrible briefing, because the background you trimmed is exactly what your assistant needed. When you talk, you ramble, you repeat yourself, you double back and add the bit you forgot. All of that is useful. It picks up not just what you want but how you think about it, and it gets better at sounding like you as a direct result.

Ramble on purpose. For anything longer than a line, talk.

What to use

  • Built into your machine, free. On a Mac, turn on Dictation in System Settings under Keyboard, then press the key it assigns you. On Windows, press Windows + H. Both are good enough to start today.
  • A dedicated tool, better. Wispr Flow is what several people running this kit use. It's noticeably more accurate on long rambling speech, it works in any application, and it's a small monthly cost. Worth it if you take to dictating, and there's no need to decide now.

Tell your assistant you dictate

Dictation mangles names. The same supplier arrives three different ways in a week, and your own product names come out as nonsense. Say this once, early:

I use dictation software to talk to you rather than typing.
That means you'll get mishearings and odd spellings,
especially on names. Work out what I meant rather than
transcribing me literally, and don't correct me on it in
your reply. When you work out that a garble maps to a real
name, remember it so it resolves on sight next time. Save
that.

From then on it decodes you instead of taking you literally, and it keeps a running list of your recurring garbles. It still won't guess a name into a document, an email or a tracker: if it isn't certain who you meant, it asks.

10A second opinion: connect Codex

Optional, and the best thing you can add in the first month.

20 minutes, and you need a paid ChatGPT plan

If you already pay for ChatGPT, you're paying for something you probably aren't using. That subscription includes Codex, OpenAI's coding assistant, and Codex can be plugged straight into your Chief of Staff as a second module it can call on.

Why that's worth twenty minutes: an assistant checking its own work is one mind doing both jobs, and it tends to find what it was already looking for. Codex is a different model from a different company that hasn't sat through your conversation and has no stake in the answer being right. Hand it something to audit and it will tell you plainly when it's wrong. That's a genuinely independent check rather than a second opinion from the same head.

What to use it for

  • Auditing what your assistant built. A new skill, a playbook, a change to your operating brief. Ask Codex whether it actually does what it claims and where it would fail.
  • Checking numbers and figures. A quote, a set of prices, anything where an arithmetic slip costs real money.
  • Verifying that something works rather than just looks finished. It will run and test things, which is the difference between "this should work" and "I ran it".
  • A second read on an important document before it goes out. Different model, different blind spots.
  • Heavy grinding work you'd rather not spend your Claude allowance on, since it draws on a separate subscription.

Setting it up

The honest version: this is the most technical thing on this page, and it's also the thing your assistant is best at doing for you. Try the easy way first.

The easy way

Ask your Chief of Staff to do it. Something like:

I have a paid ChatGPT subscription and I'd like to connect
Codex to you as a second opinion, so I can ask you to have
it audit and verify things independently. Walk me through
installing it and connecting it, one step at a time, and
tell me exactly what to paste where. Check what I already
have installed before you assume anything, and stop and
ask if a step needs a decision from me.

What it involves, so you know what you're agreeing to

  1. A paid ChatGPT plan. Plus, Pro or Business. The free tier doesn't include Codex.
  2. Node.js, a background tool much like Git, downloaded from nodejs.org. Accept the defaults.
  3. The Codex tool itself, one line in the Terminal: npm install -g @openai/codex
  4. Sign in: type codex, and choose to sign in with your ChatGPT account when it asks.
  5. Connect it to your Chief of Staff: claude mcp add codex -- codex mcp-server

Restart the Claude app afterwards. To check it worked, ask your assistant: "Is Codex connected? Ask it to say hello."

How to actually use it

You never talk to Codex directly. You ask your Chief of Staff to bring it in, and it hands over the job and reports back.

Get Codex to review the skill we just built. Don't tell it
what we were trying to do or why we made the choices we
made, just point it at the file and the standard it should
be judged against. I want its read, not its agreement with
yours. Bring me back what it found, including anything you
disagree with.

11How to run a session

The habits that make the difference.

Give a brief, not a question

A chat answers a question and leaves the doing to you. Your Chief of Staff takes the whole job.

Not "what should I say to Sarah about the half-day?" but "Draft the follow-up to Sarah, she asked about the half-day, keep it warm and short." It writes it in your voice, prices it off your own price list, and files it where it belongs.

You aren't writing prompts. You're briefing a capable colleague who already knows your business. There's a reference card on this in your kit: Briefing your Chief of Staff.

Open informed, close captured

Your assistant reads what's current before it answers anything, so you'll usually get a few lines on what's overdue, what's due today and what it suggests you focus on. That's built in rather than something you trigger.

At the other end, before you finish, check the session was captured: a dated entry in this month's log, trackers updated, anything still open written down with a date on it. The log is the one people skip and the one that pays off latest. Trackers tell you what happened. The log tells you why, and the why is what you won't be able to reconstruct next year.

Log as you go, not at the end

When something changes mid-session, a decision gets made, a task finishes, something new comes up, say so then. A week-old memory is much less useful than one written in the moment.

Correct once, and make it stick

Say what's wrong plainly, then tell it to remember. "Never open an email that way. Save that." A chat forgets. Your Chief of Staff doesn't. Every correction you bother to save is one you never make again, which means the first fortnight feels like work and the second feels like having staff.

Push back, and let it push back

If an answer is wrong, say so straight. It would rather be corrected than be politely wrong. And when it tells you something you didn't want to hear about a price or a deadline, that's it doing its job.

The rule of three

If you've done something manually three times, it should be a skill. Say "let's write this up as a skill so I don't have to explain it again", walk through it out loud once, and it writes the instructions. From then on it just runs. Common first ones: a particular kind of email, preparing for a call, checking content against your voice, generating a quote.

Before you build one, check whether it already exists. Nineteen ship with your kit and they're listed in reference/Skills-Catalogue.md inside your assistant's folder, along with good free ones other people have published. There's also a menu of ideas in Skills for inspiration.

Five minutes a week

Once a week, ask it: what got done, what's stuck, what's overdue, what's the most important thing next week. Five minutes of that saves hours of catching up, and it's how the system stays honest rather than becoming a pile of files.

Back it up

Your whole system is a folder, which makes backing it up simple and makes losing it entirely possible. The Backing it up card in your kit covers it in a couple of minutes. Do it in your first week rather than your first bad week.

12When you get stuck

Everyone hits a wall in the first fortnight.

An error popped up

Errors are normal. Paste it straight back to your assistant, or screenshot it and drop it in: "this came up, can you fix it?" Most of the time it can, and you never need to understand what the error said.

It's behaving strangely

Two causes, in order of likelihood. You're on the wrong model or effort setting, so check the picker first (step 7). Otherwise it's a stale or contradictory file: ask it to check its operating brief and its recent memory for anything out of date or clashing, then fix the source rather than adding more instructions on top. Do less, check more.

Something needs the terminal

Now and then a job needs something installed or a command run. Your assistant hands you a line to paste. Copy, paste, done. You don't need to understand it, and it isn't a sign that things have gone wrong.

Something's missing or looks different from this page

Update the Claude app, then try again. The app changes often and this page describes it as it was written.

Still stuck

Ask your assistant to get you unstuck. Describe what you were trying to do, what happened, and what you've already tried. That's the muscle worth building, and it works far more often than people expect on their first go. The Getting unstuck card has the short version to keep beside you.

Worth hearing

Being stuck is part of it rather than a sign you're doing it wrong. It passes fast, and it passes faster if you ask the assistant sitting right there before you go looking anywhere else.
